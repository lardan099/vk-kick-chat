# Merged Chat — расширение Chrome

## Что это
Общий чат Kick + VK Play Live в виде расширения Chrome: всё, что нужно для работы, держит скрытым (без окон и вкладок), сам перезапускает упавшее и сообщает о новых версиях на GitHub.

## Статус
ACTIVE

## Где исходники
- `src/merged-chat.user.js` — сам чат (юзерскрипт; по-прежнему работает и в Tampermonkey). Правится только он.
- `extension/` — расширение. `extension/chat.js` и `extension/update.json` генерирует `tools/build.mjs`, руками не править.
- Обновления берутся из `https://github.com/lardan099/vk-kick-chat` (ветка `main`, файл `extension/update.json`).
- Старая версия юзерскрипта и стенд — `08_Стримы/merged-chat-test`.

## Как запустить
Первая установка (один раз):
1. Скачать/склонировать репозиторий в постоянную папку, например `C:\MergedChat` (не в «Загрузки»).
2. Chrome → `chrome://extensions` → включить «Режим разработчика» → «Загрузить распакованное» → папка `extension`.
3. Значок расширения → «Открыть чат». Чат открывается попап-окном (ссылка `…/chat#feed`, открытая вкладкой, тоже сама уходит в попап).

Переезд с Tampermonkey (переименования, выделения, цвета, шаблоны):
- Юзерскрипт 6.43+ при каждом открытии чата оставляет свои настройки в `localStorage` kick.com (`mc_tm_export_v1`).
- Расширение при первом запуске забирает их, сливает со своими и пишет «Перенесено из Tampermonkey: N переименований».
- Поэтому сначала у человека должен обновиться юзерскрипт до 6.43 (выложить `src/merged-chat.user.js` на GreasyFork, Tampermonkey подтянет сам) и хоть раз открыться чат. Потом ставится расширение.
- Если стоят оба, юзерскрипт видит расширение и не запускается. Если он успел первым, в чате будет красная полоска «выключи его в Tampermonkey».
- Вручную (работает и со старым 6.42): значок расширения → «Настройки» → «Перенос и запасная копия…» (`transfer.html`). Вставить текст вкладки «Хранилище» скрипта в Tampermonkey или перетащить файл «Утилиты → Экспорт» (zip/json). Берутся только настройки чата (переименования, выделения, цвета, шаблоны), не токены. Там же — запасная копия в файл.
- Старый юзерскрипт (до 6.43) про расширение не знает и, если стартует позже, перерисовывает окно своим чатом без VK. Расширение замечает это и показывает поверх окна, что делать (перенести, выключить скрипт, перезагрузить).

Выпуск обновления (автор):
1. Правишь `src/merged-chat.user.js`, поднимаешь `// @version` (например `6.44`).
2. `node tools/build.mjs --notes "что нового"` — собирает `chat.js`, ставит версию в `manifest.json`, пишет `update.json` с sha256 файлов.
3. `git commit` + `git push`. У всех в течение 30 минут в чате появится полоска «Вышла версия …» → клик → страница с архивом и тремя шагами: скачать, заменить файлы в папке расширения, «Перезапустить расширение».

## Выдача подписок
- Значок подарка в шапке чата открывает быструю панель: ник/ID → срок → «Выдать» (поиск сам через 0,3 с). Полное окно `extension/gifts.html` (порт `/zapisi/manage`) — для истории выдач и из окна значка. Кнопки видны только тем, кого пускает сервер (вход на pzdcflix через Kick, аккаунт команды).
- Ключей в расширении нет: окно ходит в тот же `/api/rec/admin` сайта, где есть вход (`CONFIG.giftSites`, по куке `pzdc_session`; значение куки расширение не читает). Сервер принимает только свой Origin, поэтому для запросов самого расширения его подставляет правило DNR (id 3+). Журнал выдач, CSRF и защита от двойной оплаты — на сервере.
- Логика окна (`gifts.js`) повторяет `public/subscription-admin.js` из репозитория pzdcflix; при изменениях там переносить сюда.

## Настройки
- `extension/config.js` — адрес `update.json`, адрес чата, страницы сборщиков.
- Значок расширения → «Настройки»: где держать сборщики (скрыто / вкладки / свёрнутое окно), какие держать, гасить ли их при закрытом чате, свой адрес обновлений.
- Канал (`grpzdc`, id чатов) — как раньше, в начале `src/merged-chat.user.js`.

## Как устроено
- **Скрытый режим** (по умолчанию): в невидимом offscreen-документе расширения живут два iframe.
  - VK: страница с адреса VK, где приложение VK сразу останавливается (`window.stop`), а расширение само держит сокет `pubsub.live.vkvideo.ru` (Centrifugo). Гостевой токен сокета берётся из HTML страницы, каналы — из `api.live.vkvideo.ru/v1/blog/<канал>/public_video_stream`.
  - Адрес читателя — плеер-виджет `live.vkvideo.ru/app/embed/<канал>` (VK сам разрешает его встраивать), запасной — `robots.txt`. Если читатель не поднялся, сторож переключает адрес и запоминает рабочий (`ext_reader_ok`).
  - Kick: попап-чат Kick для истории при заходе и тайм-аутов из родного чата.
- **Токены для модерации и отправки** читаются из кук через `chrome.cookies`: Kick — `session_token`, VK — `auth` (`accessToken`). Перелогин подхватывается сразу. Вкладка dashboard.kick.com больше не нужна (осталась запасным вариантом в настройках).
- **Авторелоад**: сторож раз в 30 с проверяет heartbeat каждого сборщика и тихо перезагружает зависший или не поднявшийся; сборщики сами сообщают об ошибках (сокет VK не поднялся, не догрузились скрипты). VK API ответил 401/403 → перезапуск VK. Не больше 5 автоперезагрузок за 15 минут, дальше статус «не отвечает» и кнопка «Открыть».
- **Обновление вручную**: воркер раз в 30 минут читает `update.json` и показывает, что вышла новая версия; `updater.html` даёт архив с GitHub и кнопку перезапуска. Само расширение файлы на диск не пишет: до 6.50 оно перезаписывало свои `.js` через File System Access API, и Защитник Windows ловил это облачной эвристикой (`Trojan:Win32/Fauppod.A!cl`).
- GM_* из юзерскрипта заменяет `gm-shim.js` (синхронный кэш поверх `chrome.storage.local`), перехват WebSocket/fetch страницы делает `page-hook.js` в мире страницы.

## Известные проблемы
- Режим разработчика в Chrome должен оставаться включённым: без него Chrome отключает распакованные расширения при перезапуске.
- Обновление ручное: при замене файлов папку не удалять и не переносить — иначе у расширения сменится id и пропадут переименования (перед переносом — «Перенос и запасная копия» → копия в файл).
- Модерация и отправка с реальным логином не проверены: в тестах логина не было. Проверено, что токены из кук доходят до чата и что API VK отвечает через воркер.
- Во фреймах Chrome не даёт сайтам их куки, поэтому скрытые страницы не залогинены. Это не мешает: сообщения читаются без логина, а токены берутся из кук напрямую.
- Если в браузере уже открывали VK, у `live.vkvideo.ru` есть свой service worker (`firebase-messaging-sw.js`). Страницы VK во фрейме идут через него, и правило DNR уже не может снять с них `X-Frame-Options: DENY`. Поэтому читатель живёт на плеере-виджете, у которого этого запрета нет.
